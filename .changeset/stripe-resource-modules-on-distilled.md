The Stripe resource modules (`./Customer`, `./Invoice`, `./Treasury.FinancialAccount`, …), one subpath per Stripe API resource, are generated thin wrappers of Distilled's Stripe operations (`@distilled.cloud/stripe`), run through `StripeHttp` under the same request policy as `StripePayments` (#146).

- **Every Distilled operation on each resource.** Each module wraps all of `@distilled.cloud/stripe`'s operations on its resource, its sub-resources and test helpers included: 587 of Distilled `1.0.0-rc.15`'s 589 operations across 131 modules, one for every Stripe resource (#154), the `/v2` APIs included. Among them are the Invoice and Subscription actions (`Invoice.finalize`, `pay`, `voidInvoice`, `send`, `markUncollectible`, `addLines`, `removeLines`, `updateLines`, `updateLine`, `listLines`, `createPreview`, `attachPayment`, `search`; `Subscription.pause`, `resume`, `migrate`, `search`, `delDiscount`) and many others (`Customer.search` / `listPaymentMethods` / `createTaxId` / `testHelpersFundCashBalance`, `Charge.capture` / `listRefunds`, `PaymentIntent.capture` / `incrementAuthorization`, `Terminal.Reader.processPaymentIntent`, `Treasury.InboundTransfer.testHelpersSucceed`, …). Names follow the path (`create` / `retrieve` / `update` / `del` / `list`, an action by its name, `testHelpers…` for a test helper; `del`, `voidInvoice` and `voidCreditNote` because `delete` and `void` are reserved, with stripe-node's `Billing.CreditGrant.voidGrant` and `Apps.Secret.delWhere` (it deletes by name and scope, not by id); `list…` for a list, as in `CreditNote.listPreviewLines`; `update` for a singleton's `POST`, as in `Tax.Settings.update`).
- **Every Stripe resource has a subpath:** `./Customer`, `./Invoice`, `./CreditNote`, `./Quote`, `./InvoiceItem`, `./Plan`, `./SubscriptionItem`, `./PaymentLink`, `./Mandate`, `./Source`, `./TaxId`, `./Token`, … and the namespaced `./Billing.*`, `./BillingPortal.Configuration`, `./Tax.*`, `./Radar.*`, `./Reporting.*`, `./Sigma.ScheduledQueryRun`, `./Climate.*`, `./Entitlements.*`, `./FinancialConnections.*`, `./Forwarding.Request`, `./Apps.*`, `./ProductCatalog.TrialOffer`, `./ThreeDSecure.Authentication`, `./TestHelpers.TestClock`, `./Identity.*`, `./Issuing.*`, `./Terminal.*` and `./Treasury.*` (all ten re-exported by `./Treasury`), and the `/v2` APIs (`./V2.Billing.*`, `./V2.Commerce.ProductCatalogImport`, `./V2.Core.*`, whose params go out as JSON). The package root re-exports every module, flattened (`BillingMeter`, `V2CoreAccount`, …); the README lists them all. Two operations stay unwrapped because the client cannot run them: `GET /v1/quotes/{quote}/pdf` (a binary PDF from `files.stripe.com`) and `POST /v2/billing/meter_event_stream` (`meter-events.stripe.com`, authenticated by a session token): call `@distilled.cloud/stripe` directly for those.
- **Signature.** An operation takes the resource's path ids first, as strings in path order (`Person.retrieve(accountId, personId)`), then the rest of Distilled's input as `params` (optional unless Distilled requires a member; absent when there is nothing else), then `options?: RequestOptions`. It requires `StripeHttp` and fails only with the neutral `PaymentsError` channel. A path id that is not a non-empty string fails with `PaymentInvalidRequestError` before anything is sent. Because of the trailing arguments, wrap an operation before passing it to an index-supplying iterator: `Effect.forEach(ids, (id) => Customer.del(id))`, not `Effect.forEach(ids, Customer.del)`.
- **`RequestOptions`** (`StripeHttp.RequestOptions`, also exported from the root): `idempotencyKey` (sent as `Idempotency-Key`; create one per logical write and reuse it on every retry), `stripeAccount` (`Stripe-Account`, overriding the configured one) and `apiVersion` (`Stripe-Version` for this one call, overriding the configured one and `DISTILLED_API_VERSION`). An empty value fails with `PaymentInvalidRequestError` before anything is sent.
- **Types are Distilled's.** Every parameter and result is typed with `@distilled.cloud/stripe`'s declarations, and each module re-exports its operations' input and output types, each also a `Schema` (`Customer.Customer`, `Customer.DeletedCustomer`, `Customer.CreateCustomerRequest`, `Customer.GetCustomersResponse`, …). A request type includes the path ids (`GetCustomerRequest` has `customer`); the `params` argument is it without them.
- **Responses are not validated.** A result is the response as Stripe sent it, typed as Distilled's output (a body that is not JSON fails with `PaymentProviderError`). Response enumerations are plain `string`s. Distilled's types describe `2026-09-30.endive`: at an older `apiVersion`, a field they mark required may be absent. `CheckoutSession.create`, `PaymentIntent.create` / `confirm` / `update` and `SetupIntent.create` / `update` take endive's params: `allowed_payment_method_types`, not `payment_method_types`. `Subscription.update`'s `billing_cycle_anchor` is an object, `{ type: "now" | "unchanged" }`.
- **Gaps inherited from Distilled `1.0.0-rc.15`.** `Transfer.create` / `retrieve` / `update` resolve to `unknown`, and `Transfer.list`'s `data` to `Array<unknown>`, because Distilled declares no Transfer schema. Distilled's input types declare optional members as bare `?: T`, so under `exactOptionalPropertyTypes` a caller that forwards an optional of its own must omit an absent member rather than pass `undefined`.
- **Uploads.** `File.create` takes the file in `file` as a `Blob` (a `File` included; Distilled declares it `string`, so the module retypes it `string | Blob`), sent as a `multipart/form-data` part to `files.stripe.com` (or `uploadsBaseUrl`), with nested params (`file_link_data`, `expand`) as bracketed fields.
- **The SDK-based webhook verifier.** `Webhook.constructEvent` / `constructEventAsync` / `generateTestHeaderString*` run on a `stripe` SDK client your program builds and provides, `Layer.succeed(Webhook.StripeService, new Stripe(key))` (they use only the endpoint secret). No module loads `stripe`: it is an optional peer (`^23.0.0`, the stripe-node major for `2026-09-30.endive`, the `Stripe-Version` every request pins, so `constructEvent*`'s `Stripe.Event` describes the events an endpoint at that version receives, an exact match on 23.0.x (a later 23.x types events at its own, newer endive version)), needed only for the types of `./Webhook` and the package root. For them, a `tolerance` of `0` means the default 300 s and a negative tolerance skips the timestamp check, whereas `Webhook.verify` reads `0` as "this second only".
- **Type-checking cost.** A resource module's declarations name Distilled's operations module, one declaration file of about 7.5 MB, so a program that imports any resource module (or the package root) type-checks it. For a one-line consumer of one module (with `skipLibCheck`) that is about 0.45–0.5 s with the native `tsc` and 1.9–2.0 s with TypeScript 6's `tsc`. `./StripePayments`, `./StripeHttp` and `./Webhook` never reach it.
