The Stripe resource modules (`./Customer`, `./Invoice`, `./Treasury.FinancialAccount`, …) are thin wrappers of Distilled's Stripe operations (`@distilled.cloud/stripe`), run through the same client and request policy as `StripePayments` (#146). Every subpath stays published.

- **New: every Distilled operation on each resource.** Each module now wraps all of `@distilled.cloud/stripe`'s operations on its resource, its sub-resources and test helpers included: 288 operations across the 45 modules, where there were 180. That includes the Invoice and Subscription actions #142 asked for (`Invoice.finalize`, `pay`, `voidInvoice`, `send`, `markUncollectible`, `addLines`, `removeLines`, `updateLines`, `updateLine`, `listLines`, `createPreview`, `attachPayment`, `search`; `Subscription.resume`, `migrate`, `search`, `delDiscount`), and many others (`Customer.search` / `listPaymentMethods` / `createTaxId` / `testHelpersFundCashBalance`, `Charge.capture` / `listRefunds`, `PaymentIntent.capture` / `incrementAuthorization`, `Terminal.Reader.processPaymentIntent`, `Treasury.InboundTransfer.testHelpersSucceed`, …). The names follow the path; every name a module exported before is kept, except the two below. Operations on resources with no subpath (credit notes, quotes, tax, Radar, the `v2` APIs, …) are not wrapped: call `@distilled.cloud/stripe` directly for those.
- **Breaking: types are Distilled's.** Every parameter and result is typed with `@distilled.cloud/stripe`'s declarations, where the modules used the `stripe` package's types or this package's generated schemas. Each module re-exports its operations' input and output types, each also a `Schema` (`Customer.Customer`, `Customer.DeletedCustomer`, `Customer.CreateCustomerRequest`, `Customer.GetCustomersResponse`, …). The generated names the eight migrated modules exported map onto Distilled's: `<X>List` → `Get<Xs>Response` (`Customer.CustomerList` → `Customer.GetCustomersResponse`); `<X>CreateParams` → `Create<X>Request`; `<X>RetrieveParams` → `Get<X>Request`; `<X>UpdateParams` → `Update<X>Request`; `<X>ListParams` → `Get<Xs>Request`; `SubscriptionCancelParams` → `DeleteSubscriptionRequest`; `SubscriptionSchedule<Op>Params` → `CreateSubscriptionSchedule<Op>Request` (`Cancel`, `Release`) and `CreateSubscriptionScheduleRequest` / `UpdateSubscriptionScheduleRequest`; `CheckoutSession.Session` → `CheckoutSession.CheckoutSession`, `SessionList` → `GetCheckoutSessionsResponse`, `SessionExpireParams` → `CreateCheckoutSessionExpireRequest`; `BillingPortal.Session.Session` → `BillingPortalSession`, `SessionCreateParams` → `CreateBillingPortalSessionRequest`. A request type includes the path ids (`GetCustomerRequest` has `customer`); the `params` argument is it without them. `retrieve` on a customer answers `GetCustomerResponse` (a customer, or a deleted one). Distilled's input types declare optional members as bare `?: T`, so under `exactOptionalPropertyTypes` a caller that forwards an optional of its own must omit an absent member rather than pass `undefined`. `Transfer.create` / `retrieve` / `update` resolve to `unknown`: Distilled `1.0.0-rc.13` declares them so.
- **Breaking: responses are not validated, and enumerations are plain strings.** A result is the response as Stripe sent it, typed as Distilled's output, never decoded: the eight modules that decoded with generated schemas (`CheckoutSession`, `BillingPortal.Session`, `Customer`, `Product`, `Price`, `Subscription`, `SubscriptionSchedule`, `Invoice`) no longer fail a malformed 2xx with `PaymentProviderError` (a body that is not JSON still does), and their response enumerations are plain `string`s rather than the core's lenient `Enumeration` (`Known | Other`). An expandable field is typed as Distilled types it. Distilled's types describe `2026-07-29.dahlia`: at an older `apiVersion`, a field they mark required may be absent.
- **Breaking: the resource modules move to Stripe API version `2026-07-29.dahlia`.** They and `StripeHttp` pin `Stripe-Version` to `DISTILLED_API_VERSION`, the version the capability layers already pin, instead of `2025-08-27.basil`; it follows Distilled, so a release that moves the Distilled pin moves it too. `StripeHttp.DEFAULT_API_VERSION` is removed: use `StripeHttp.DISTILLED_API_VERSION` (also exported by `StripePayments`). An explicit `apiVersion` in the configuration still wins, and `RequestOptions` gains `apiVersion`, which overrides both for one call (`Customer.retrieve(id, undefined, { apiVersion: "2025-08-27.basil" })`; an empty one fails with `PaymentInvalidRequestError`). Move webhook endpoints, and any code of yours that reads Stripe's JSON, to `2026-07-29.dahlia`.
- **Breaking: `./Stripe` is removed.** The SDK transport (`Stripe.layer`, `Stripe.layerFromEnv`, `Stripe.make`, `Stripe.transport`, `Stripe.StripeClient`, `StripeConfig`) is gone: the resource modules run only on `StripeHttp`. `StripeService` moves to `Webhook.StripeService`: the SDK-based `Webhook.constructEvent` / `constructEventAsync` / `generateTestHeaderString*` stay, on an SDK client you build, `Layer.succeed(Webhook.StripeService, new Stripe(key))` (they use only the endpoint secret). No module loads `stripe` any more; the optional peer is only for those functions' types.
- **Breaking: `StripeHttp` is the Distilled client.** `StripeHttp`'s service is `call(method, operation, input, options?)` (a Distilled operation under the request policy), not `request({ method, path, params, … })`, so a raw call by path or a fake `StripeHttp.request` no longer works: call the operation's resource module, or `@distilled.cloud/stripe` directly. `StripeHttp.layer` / `layerFromEnv` / `layerConfig` / `make` keep their signatures and configuration (`baseUrl` and `uploadsBaseUrl` included); `StripeHttp.layerFromContext` is new (over Distilled's `Credentials` in context). `StripeRequest` and `StripeMethod` are removed (`Method` and `Operation` describe `call`). Every call now needs a `process` global, as the capabilities already do (on Cloudflare Workers, the `nodejs_compat` flag), because Distilled reads `process.env.DISTILLED_DEBUG_HTTP` on every request.
- **Breaking: renamed and removed operations.** Positional arguments are the path ids, then `params`, then `options`, as before, but five operations gained a `params` argument before `options`, so a call passing options second must pass `undefined` (or the params) first: `Identity.VerificationSession.cancel` / `redact`, `Treasury.FinancialAccount.close`, `Treasury.InboundTransfer.cancel` and `Treasury.OutboundTransfer.cancel`. `params` became optional on several creates (`Account.create`, `Charge.create`, `Invoice.create`, `PaymentMethod.list`, `PaymentMethod.attach`, …). `Issuing.Authorization.approve` and `decline` are removed: Distilled (Stripe's `2026-07-29.dahlia` spec) has no operation for them; Stripe deprecated those endpoints in favour of answering the `issuing_authorization.request` webhook. No other name changed.
- **Breaking: `File.create` takes Distilled's input.** The file goes in `file` as a `Blob` or `File` (Distilled declares it `string`, so cast it), sent as a `multipart/form-data` part to `files.stripe.com` as before, with nested params (`file_link_data`, `expand`) as bracketed fields; the old `{ data, name, type }` part object is not accepted.
- **Unchanged.** The request policy (retries with one `Idempotency-Key` per write, the per-attempt timeout, refused redirects, the neutral error mapping with the whole vendor error object as the cause), the empty-id refusal (`PaymentInvalidRequestError` before anything is sent) and the `layerConfig` "not configured ≡ down" posture carry over. The root entry still exports `StripeErrors` (the neutral `PaymentsError`), `RequestOptions` and `StripeHttpConfig`.
- **Type-checking cost.** A resource module's declarations name Distilled's operations module, one declaration file of about 7.5 MB, so a program that imports any resource module (or the package root) type-checks it. For a one-line consumer of one module that is about 0.5 s with the native `tsc` (+0.07 s against a resource module before this release, with slightly less memory) and 1.8 s with TypeScript 6's `tsc` (+0.1–0.2 s, +15 MiB). `./StripePayments`, `./StripeHttp` and `./Webhook` still never reach it. The package's own `dist/` shrinks from about 3.9 MB to under 0.5 MB, since the generated schemas are gone.
