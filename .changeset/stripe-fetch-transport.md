**Breaking:** the Stripe provider runs on a fetch-only transport, and the `stripe` SDK is an optional peer.

- **New `StripeHttp` transport** (`@thomasfosterau/effect-payments-stripe/StripeHttp`) over `effect/unstable/http`'s `HttpClient`, with no Node API and no SDK, so it runs in a Cloudflare Worker. It form-encodes parameters the way the SDK does (`metadata[key]`, `items[0][price]`), pins `Stripe-Version` (`DEFAULT_API_VERSION`, `2025-02-24.acacia`, unless `apiVersion` is set), sends the key as a `Redacted` bearer token, refuses redirects, and retries connection failures, `409`s and `5xx`s with the SDK's backoff and `Stripe-Should-Retry` handling. Each `POST` that may be retried gets one generated `Idempotency-Key` for all of its attempts. Stripe's error envelope is decoded with `Schema` onto the neutral errors, with the same mapping as before: authentication → `PaymentAuthenticationError`, rate limit → `PaymentRateLimitError` (with `Retry-After`), invalid request → `PaymentInvalidRequestError` (with `param`), connection → `PaymentNetworkError`, anything else → `PaymentProviderError`.
- **Resource modules** (`Customer`, `Treasury.FinancialAccount`, …) now require `StripeHttp` instead of `StripeService`. Their parameters and results are the same `stripe` types as before. `Terminal.Location` and `Terminal.Reader` `retrieve` / `update` now return the SDK's `T | DeletedT` union, because Stripe answers a deleted object with its `{ deleted: true }` stub.
- **`StripePayments.layer` / `layerFromEnv`** run on the fetch transport and require an `HttpClient`, as the PayPal and Airwallex layers do. Provide `FetchHttpClient.layer`. `StripePayments.capabilities` and the individual capability layers require `StripeHttp`. Every response they read is decoded with `Schema`, so a malformed 2xx fails with `PaymentProviderError`. Subscriptions read the billing period from the first item when the API version puts it there (2025-03-31 "basil" and later), and otherwise from the subscription.
- **API keys are `Redacted`.** `StripeHttpConfig.apiKey` and `StripeConfig.apiKey` are `Redacted<string>`, and `layerFromEnv` reads the key with `Config.Redacted`.
- **The SDK is an optional alternative.** `stripe` moved from `dependencies` to an optional peer dependency. The `Stripe` module (`@thomasfosterau/effect-payments-stripe/Stripe`) is now the SDK transport: `Stripe.layer` / `layerFromEnv` provide the SDK client (`StripeService`) and `StripeHttp` over `stripe.rawRequest`. It is the only module that loads `stripe` at runtime, and it is no longer re-exported from the package root. The barrel exports `StripeHttp` and the `StripeHttpConfig` type in its place. Install `stripe` (as a dev dependency) for the resource modules' types, and at runtime for `Stripe.layer` or the SDK-based `Webhook` verifier, which still needs `StripeService` until the WebCrypto verifier lands.
