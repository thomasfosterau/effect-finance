The Stripe provider runs on a fetch-only transport, and the `stripe` SDK is an optional peer.

- **`StripeHttp` transport** (`@thomasfosterau/effect-payments-stripe/StripeHttp`) over `effect/http`'s `HttpClient`, with no Node API and no SDK, so it runs in a Cloudflare Worker. It form-encodes parameters the way the SDK does (`metadata[key]`, `items[0][price]`), pins `Stripe-Version` (`DEFAULT_API_VERSION` unless `apiVersion` is set), sends the key as a `Redacted` bearer token, refuses redirects, and retries connection failures, `409`s and `5xx`s with the SDK's backoff and `Stripe-Should-Retry` handling. Each `POST` that may be retried gets one generated `Idempotency-Key` for all of its attempts. Stripe's error envelope is decoded with `Schema` onto the neutral errors: authentication → `PaymentAuthenticationError`, rate limit → `PaymentRateLimitError` (with `Retry-After`), invalid request → `PaymentInvalidRequestError` (with `param`), connection → `PaymentNetworkError`, anything else → `PaymentProviderError`.
- **Resource modules** (`Customer`, `Treasury.FinancialAccount`, …) require `StripeHttp`, and take and return the `stripe` package's types. `Terminal.Location` and `Terminal.Reader` `retrieve` / `update` return the SDK's `T | DeletedT` union, because Stripe answers a deleted object with its `{ deleted: true }` stub.
- **`StripePayments.layer` / `layerFromEnv`** run on the fetch transport and require an `HttpClient`, as the PayPal and Airwallex layers do: provide `FetchHttpClient.layer`. `StripePayments.layer` takes a `StripeHttpConfig` (`apiKey`, `apiVersion`, `maxNetworkRetries`, `timeout`, `stripeAccount`, `baseUrl`, `uploadsBaseUrl`); `appInfo` exists only on the SDK transport's `StripeConfig`, because the fetch transport sends no SDK user agent. `StripePayments.capabilities` and the individual capability layers require `StripeHttp`. Every response they read is decoded with `Schema`, so a malformed 2xx fails with `PaymentProviderError`. Subscriptions read the billing period from the first item when the API version puts it there (2025-03-31 "basil" and later), and otherwise from the subscription.
- **Errors keep Stripe's details.** Error fields Stripe sends as `null` (such as `"code": null`) are read as absent, so the error is still classified by its `type`. A `PaymentProviderError`'s `cause` is Stripe's whole error object as received, including `decline_code`, `payment_intent`, `advice_code` and the rest.
- **A missing or empty id fails.** A resource-module or capability call with an empty (or, from untyped code, non-string) id fails with `PaymentInvalidRequestError` and sends no request, rather than addressing the list endpoint.
- **API keys are `Redacted`.** `StripeHttpConfig.apiKey` and `StripeConfig.apiKey` are `Redacted<string>`, and `layerFromEnv` reads the key with `Config.Redacted`.
- **The SDK is an optional alternative.** `stripe` is an optional peer dependency. The `Stripe` module (`@thomasfosterau/effect-payments-stripe/Stripe`) is the SDK transport: `Stripe.layer` / `layerFromEnv` provide the SDK client (`StripeService`) and `StripeHttp` over `stripe.rawRequest`. It is the only module that loads `stripe` at runtime, and it is not re-exported from the package root, which exports `StripeHttp` and the `StripeHttpConfig` type. Install `stripe` (as a dev dependency) for the resource modules' types, and at runtime for `Stripe.layer` or the SDK-based `Webhook.constructEvent*` verifier.
