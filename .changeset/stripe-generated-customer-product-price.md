The `Customer`, `Product` and `Price` resource modules are typed by Schemas generated from Stripe's OpenAPI spec, with their responses decoded (the first slice of migrating the remaining resource modules off the `stripe` package's types).

- **`Customer`** (`create`, `retrieve`, `update`, `del`, `list`), **`Product`** (`create`, `retrieve`, `update`, `del`, `list`) and **`Price`** (`create`, `retrieve`, `update`, `list`) export their Schemas (`Customer`, `DeletedCustomer`, `CustomerList`, `Product`, `DeletedProduct`, `ProductList`, `Price`, `PriceList`) and parameter types (`CustomerCreateParams`, `CustomerRetrieveParams`, `CustomerUpdateParams`, `CustomerListParams`, and the same four for `Product` and `Price`). Every response is decoded, and a 2xx body that does not match fails with `PaymentProviderError` instead of being cast. Their emitted `.d.ts` files do not import `stripe`, so a consumer of only these modules (and `CheckoutSession` / `BillingPortal.Session`) needs no `stripe` types.
- **Type changes.** The results are no longer `Stripe.Customer`, `Stripe.Product`, `Stripe.Price`, `Stripe.DeletedCustomer`, `Stripe.DeletedProduct` or `Stripe.ApiList<…>`, and the parameters are no longer the SDK's `…CreateParams` / `…UpdateParams` / `…ListParams`; the SDK-only parameters the pinned spec does not name are gone (`validate` on `CustomerCreateParams` and `CustomerUpdateParams`, `type` on `ProductCreateParams` and `ProductListParams`, and `recurring.trial_period_days` on `PriceCreateParams`). An expandable field (`default_source`, `test_clock`, `default_price`, `product`, …) decodes as its id or, when expanded, an open JSON object. Response enumerations (`tax_exempt`, `type`, `billing_scheme`, `recurring.interval`, …) are lenient, so code that exhaustively matches one must also handle `Enumeration.Other`; request enumerations stay closed to the pinned spec. A `deepObject` list filter is a flat, bracketed key (`Price.list({ "recurring[interval]": "month" })`), which is also its wire name.
- **Parameter values the SDK 18.5 types accepted and the generated ones do not.** "Unset" is spelled `""` only: the SDK's `Emptyable` also took `null` (`Customer.update(id, { address: null })`, `Product.update(id, { url: null })`, `Price.update(id, { metadata: null })`). `metadata` values must be strings: the SDK also took `number` and `null` (`Customer.update(id, { metadata: { n: 3 } })`, `{ metadata: { k: null } }`). On the wire nothing changes (`null` was already sent as `""`).
- The neutral capability layers (`StripePayments.customersLayer`, `productsLayer`, `pricesLayer`) are unchanged.
