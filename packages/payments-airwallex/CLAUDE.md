# @thomasfosterau/effect-payments-airwallex

Airwallex payment acceptance: `Customers`, `PaymentIntents` and `Refunds`. Peer: `effect`. Dependency: the core. No vendor SDK. Requires `HttpClient` (`effect/http`).

## Boundary

Imports only `@thomasfosterau/effect-payments` from this workspace (`.fallowrc.json` zone `airwallex`, allow `core`).

## Invariants

- **Every call goes through `HttpClient`**, never `globalThis.fetch`: the layers require `HttpClient.HttpClient`, so a consumer provides `FetchHttpClient.layer` and a test stubs `FetchHttpClient.Fetch`. Every body is decoded with `Schema`: token and error bodies in the client, resource bodies in the capability layers — `request` returns `unknown`, and each layer pipes it through a `decode*` from `internal/mapping.ts` (a wire `Schema` narrowed to the fields the mapping reads), so a 2xx that does not decode fails with `PaymentProviderError`. Statuses decode as strings; the `to*Status` functions map a recognised one onto the neutral literal and an unrecognised one onto `Enumeration.Other` carrying the raw string (never a silent neutral fallback, never a decode failure).
- **Login sharing and timeouts:** see `packages/payments/CLAUDE.md` (`shareLogin`, "One login at a time", "Every exchange is time-boxed"). Provider-specific: `getToken` is `shareLogin(cachedToken, login)`; a 401 on a resource request clears the cached token, only if it is still the token that request used; `loginTimeout` defaults to 30 s and `timeout` to 80 s (the Stripe client's per-attempt default); a caller makes a timed-out non-GET safe to retry with `AirwallexRequest.requestId` (below).
- **`requestId` becomes the body's `request_id`, `POST` only.** The client copies it over any `request_id` the capability layer put in the body (or creates the body); one id per logical write, created before the first attempt and reused by every retry. An empty id, a non-`POST`, or a body that is not a JSON object fails with `PaymentInvalidRequestError` before anything is sent. Length (about 64) and replay window are unverified (#93). The capability layers pass the neutral `idempotencyKey` of a create / confirm through `IdempotencyKey.validate` into `requestId`; with no key the body keeps its fresh `request_id`.
- **`Content-Type: application/json` on every request**, body or not: the pre-HttpClient behaviour, kept consistent with the PayPal provider's requests.
- **Configuration from the environment is read through `Config`** in `layerFromEnv`, and a missing or empty variable still fails with `PaymentConfigError`. Effect rc.118's `ConfigProvider` treats a literal empty string as a missing value, so an empty variable is the same as an unset one: an empty id or secret fails with `PaymentConfigError`, and an empty `AIRWALLEX_BASE_URL` falls back to the `AIRWALLEX_ENV` endpoint. A provider built with `preserveEmptyStrings: true` restores the old reading, which is the safer one for `AIRWALLEX_BASE_URL`: a blank stays `""` and `make` refuses it with `PaymentConfigError` (a `baseUrl` must be an absolute http(s) URL), instead of silently selecting an environment's endpoint.
- **`AIRWALLEX_ENV` is required** (`live` | `sandbox`, read with `Config.Literals`): `layerFromEnv` never selects live by default (#90). It maps onto `AirwallexConfig.environment` (`live` → `https://api.airwallex.com`, `sandbox` → `https://api.sandbox.airwallex.com`); `baseUrl` / `AIRWALLEX_BASE_URL`, when set, wins. In `make` / `layer`, `environment` is optional and defaults to `live`.
- **Only the capabilities Airwallex supports.** A program using just customers, payment intents and refunds runs unchanged on Stripe or Airwallex; one needing products or prices does not type-check against this layer.
- **Money crosses the boundary as major-unit decimals** (`internal/money.ts`, zero-decimal currencies included); the core stays in minor units. Neither direction scales with float arithmetic (#68). A response amount is parsed from `String(n)`, the shortest form of the double `JSON.parse` produced, with `BigInt` scaling. It is checked against its currency inside the wire `Schema`: excess decimals, an unsafe minor-unit amount, or an **ambiguous** double (one that a decimal half a minor unit away also parses to) fail the decode. Wire digits finer than a double resolves are undetectable in principle. A partial-refund amount is checked with `checkMinorUnits` before its currency lookup. A request amount goes through `toMajorNumber`, which refuses a negative, non-safe-integer or not-exactly-representable amount, or one whose JSON number `parseMinorUnits` would refuse to read back, with `PaymentInvalidRequestError` — so every amount sent can be decoded from Airwallex's echo. The exponent table is Stripe's plus `ISK` at 0, reviewed by the owner against summaries of Airwallex's currency pages rather than the live pages (#74); `HUF` / `IDR` / `TWD` stay at 2 and `IQD` / `LYD` at 3 (ISO 4217).
- **Vendor error bodies become neutral errors in `internal/error.ts`.** The API key and the bearer token never appear in one: the API key is `Redacted<string>` in the config (read with `Config.Redacted` in `layerFromEnv`) and unwrapped only where the login request is built, and a transport failure keeps only the underlying cause — never the `HttpClientError`, whose request carries the credential headers.

## Terms

- **Client** — `AirwallexClient` (`Airwallex.ts`): the client-id + API-key login handshake whose token is cached in a `Ref` and refreshed a minute before expiry, plus one `request` function every capability goes through. `Airwallex.layer` / `layerFromEnv` (`AIRWALLEX_CLIENT_ID`, `AIRWALLEX_API_KEY`, required `AIRWALLEX_ENV`, optional `AIRWALLEX_BASE_URL` override).
- **Capability layers** — `AirwallexPayments.*Layer`, `capabilities`, `layer` / `layerFromEnv`.
