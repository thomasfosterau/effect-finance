  - **Stripe:** payment intent `status`, subscription `status`, refund `status`, price `type` and recurring `interval` decode leniently, so one unrecognised value never fails the call or its list page.

- [#87](https://github.com/thomasfosterau/effect-finance/pull/87) [`9bbb1ad`](https://github.com/thomasfosterau/effect-finance/commit/9bbb1ad8b8e3f1b07823132edc48b628dddf4f63) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - A neutral, branded `idempotencyKey` on the create and confirm operations, so a caller's retry of a timed-out write is one logical write on every provider (closes [#55](https://github.com/thomasfosterau/effect-finance/issues/55) and [#66](https://github.com/thomasfosterau/effect-finance/issues/66)).

  - **Core.** New `IdempotencyKey` module (`@thomasfosterau/effect-payments/IdempotencyKey`, also exported from the barrel): a branded `Schema` for a key of 1 to 64 characters from `A-Z a-z 0-9 _ -`, `IdempotencyKey.generate` (a random UUID, as an `Effect`) and `IdempotencyKey.validate`. The optional `idempotencyKey?: IdempotencyKey` is added to `Customer.CreateParams`, `Product.CreateParams`, `Price.CreateParams`, `PaymentIntent.CreateParams` / `ConfirmParams`, `Subscription.CreateParams`, `Refund.CreateParams` and `CheckoutSession.CreateParams` (every create / confirm that each provider implementing it can honour). It is not on updates, `Subscription.cancel`, `PaymentIntent.cancel` or `BillingPortal.create`. The key is optional.
  - **Stripe, PayPal, Airwallex.** Each maps the key onto its vendor mechanism: `Idempotency-Key`, `PayPal-Request-Id`, and the body's `request_id` (in place of the fresh per-call id). A key that is not a valid `IdempotencyKey` (a raw string from untyped code) fails with `PaymentInvalidRequestError` before anything is sent.

  - Stripe's and Airwallex's key-length limits and replay windows could not be checked against their documentation and are documented as unverified (PayPal's: see its own entry).

- [#147](https://github.com/thomasfosterau/effect-finance/pull/147) [`3eab272`](https://github.com/thomasfosterau/effect-finance/commit/3eab272b94ca5a64cc2b67ec918ad1df191c970b) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - The Stripe provider runs on Distilled's Stripe operations (`@distilled.cloud/stripe`), through one client, `StripeHttp`, under this package's own request policy ([#146](https://github.com/thomasfosterau/effect-finance/issues/146)).

  - **Dependencies.** `@distilled.cloud/stripe` and `@distilled.cloud/core`, both pinned exactly to `1.0.0-rc.15` (about 30 MB installed, with core's `graphql` dependency). A bundler keeps only the operations the capabilities you use call: a bundle of `customersLayer` alone is about 63 KB minified (20 KB gzipped), and one of every capability about 178 KB (43 KB gzipped), with `effect` external.
  - **The `effect` peer is `^4.0.0`.** Distilled declares the peer `effect: ^4.0.0`, which no `4.0.0-rc.*` prerelease satisfies, so this package requires the same. The core and the Airwallex provider accept `>=4.0.0-rc.118`.
  - **Every call needs a `process` global.** Distilled reads `process.env.DISTILLED_DEBUG_HTTP`, unguarded, on every request and response, so without a `process` global every capability or resource-module call dies with a defect. On Cloudflare Workers, enable the `nodejs_compat` compatibility flag. Building the layers does not need it, a `layerConfig` call made while the key is unset still fails with `PaymentsUnavailable` before Distilled runs, and `Webhook.verify` never needs it. Leave `DISTILLED_DEBUG_HTTP` unset outside local debugging: while it is set, Distilled logs every request's method and URL and the first 400 characters of every request and response body to `console.error`, which can include part or all of a `client_secret`. It does not log the `Authorization` header.
  - **Stripe API version `2026-09-30.endive`, following Distilled.** Every request (retries included) pins `Stripe-Version` to `DISTILLED_API_VERSION` (exported by `StripePayments` and `StripeHttp`), the API version the pinned `@distilled.cloud/stripe` release's schemas are generated from. A later release that moves the Distilled pin moves this version too, and says so in its changelog. An explicit `apiVersion` in the configuration wins. Stripe delivers webhook events at the receiving endpoint's API version, so create the endpoints whose events you read at `2026-09-30.endive`, and keep any code of yours that reads Stripe's JSON directly (event payloads, your own calls) on the same version.
  - **`StripeHttp`, the client.** Its service is `call(method, operation, input, options?)`: one Distilled operation run under the request policy. `StripeHttp.layer` / `layerFromEnv` / `layerConfig` / `make` build it from a `StripeHttpConfig` (`apiKey`, `apiVersion`, `maxNetworkRetries`, `timeout`, `stripeAccount`, `baseUrl`, `uploadsBaseUrl`), and `StripeHttp.layerFromContext` from Distilled's `Credentials` in context. It runs over `effect/http`'s `HttpClient` with no SDK and no Node API beyond a `process` global. `uploadsBaseUrl` is ignored by the capability layers (no capability uploads). The policy:
    - the key is a `Redacted<string>` (`layerFromEnv` reads it with `Config.Redacted`) and is sent as a bearer token;
    - Distilled's own retries are off: connection failures, `409`s and `5xx`s are retried with the SDK's backoff and `Stripe-Should-Retry` handling, and each retryable `POST` sent without a caller's key gets one generated `Idempotency-Key` for all of its attempts;
    - each attempt times out (80 s by default), and redirects are refused;
    - a `DELETE`'s params are sent in the query string, as the Stripe SDKs send them;
    - Distilled's response validation is lenient, even under its `ResponseValidation.strict`, so a response is never refused over a field nobody reads.
  - **Errors.** Every failure is mapped onto the neutral `PaymentsError` channel; no Distilled error class reaches a caller. Stripe's error envelope is decoded with `Schema`: authentication → `PaymentAuthenticationError`, rate limit → `PaymentRateLimitError` (with `Retry-After`), invalid request → `PaymentInvalidRequestError` (with `param`), connection → `PaymentNetworkError`, anything else → `PaymentProviderError`. A `401`, `403` or `429` status wins over the body's `type`, as in the SDK. Error fields Stripe sends as `null` (such as `"code": null`) are read as absent, and a `PaymentProviderError`'s `cause` is Stripe's whole error object as received (`decline_code`, `payment_intent`, `advice_code`, …). The key never reaches an error.
  - **The capability layers.** `StripePayments.layer` / `layerFromEnv` / `layerConfig` take the client's configuration and need an `HttpClient` (`FetchHttpClient.layer`). `customersLayer` … `billingPortalSessionsLayer` and `capabilities` require Distilled's `Credentials` (from `@distilled.cloud/stripe/Credentials`, e.g. `Credentials.credentials({ apiKey: Redacted.make(key) })`) and an `HttpClient`; providing `Credentials` yourself means depending on `@distilled.cloud/stripe` at exactly this package's version of it. Every response a capability reads is decoded with a `Schema` narrowed to the fields it maps, so a malformed 2xx fails with `PaymentProviderError`. Subscriptions read the billing period from the first item when the API version puts it there (2025-03-31 "basil" and later), and otherwise from the subscription.
  - **A missing or empty id fails.** A capability call with a path id that is not a non-empty string fails with `PaymentInvalidRequestError` (`The customer id must be a non-empty string`, `param: "id"`) and sends nothing.

- [#60](https://github.com/thomasfosterau/effect-finance/pull/60) [`df5aa7b`](https://github.com/thomasfosterau/effect-finance/commit/df5aa7be99148b0e103cc6d8c79990103405f21c) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - `Webhook.verify` is the default webhook verifier: a Workers-safe WebCrypto implementation that needs neither the `stripe` SDK nor any Node API ([#41](https://github.com/thomasfosterau/effect-finance/issues/41)).

  - **`Webhook.verify({ payload, header, secret, tolerance? })`** checks the `Stripe-Signature` header (HMAC-SHA256 over `${t}.${rawBody}`, every `v1` digest compared in constant time, so secret rotation works), refuses a timestamp more than `tolerance` seconds either side of now (default `DEFAULT_TOLERANCE`, 300 s; "now" comes from Effect's `Clock`), and then decodes the event envelope. The secret is a `Redacted<string>`; the payload is the raw body — canonically its bytes (`new Uint8Array(await request.arrayBuffer())`), or a string as a lossy convenience. `tolerance: 0` means "the same second" here (the SDK's `constructEvent` reads it as "no check"); an unusable tolerance or an empty secret refuses the delivery. A refusal is a `SignatureVerificationError` whose `message` is one of the exported constants (`MALFORMED_HEADER_MESSAGE`, `OUTSIDE_TOLERANCE_MESSAGE`, `SIGNATURE_MISMATCH_MESSAGE`, `INVALID_TOLERANCE_MESSAGE`, `SIGNATURE_UNAVAILABLE_MESSAGE`) and which never carries the secret or the payload; nothing is decoded until the signature verifies, and a signed body that is not an event fails with `Schema.SchemaError`.
  - **`Webhook.verifySignature`** (the check alone), **`Webhook.signatureHeader`** (sign a payload as Stripe does, without the SDK — for tests and tooling only) and **`Webhook.SIGNATURE_HEADER`**.
  - **Lenient event decoders**: `WebhookEvent` / `decodeEvent`, `handledEventTypes` / `isHandledEventType`, `HandledEvent` / `decodeHandledEvent` (a `type`-discriminated union, `none` for unhandled types), and `CheckoutSessionObject`, `SubscriptionObject`, `InvoiceObject` with `decodeCheckoutSession`, `decodeSubscription`, `decodeInvoice`. `InvoiceObject` decodes the subscription from both the legacy top-level `subscription` and `parent.subscription_details.subscription` (API `2025-03-31.basil` and later); `invoiceSubscription` reads it, preferring the newer location.

  The SDK-based `Webhook.constructEvent` / `constructEventAsync` / `generateTestHeaderString*` remain available as the optional alternative (they need the `stripe` peer and an SDK client provided as `Webhook.StripeService`).
