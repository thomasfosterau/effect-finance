# @thomasfosterau/effect-payments-stripe

Stripe: the neutral capabilities as `Layer`s (`StripePayments`) over Distilled's generated Stripe operations (`@distilled.cloud/stripe`, #146), plus one resource module per Stripe API resource as a provider escape hatch over a fetch-only transport (`StripeHttp`). Peers: `effect` at `^4.0.0` (`catalogs.peers-distilled`: Distilled's own peer range, which excludes `4.0.0-rc.*`; the other packages keep `catalogs.peers`' `>=4.0.0-rc.118`), and `stripe` **optional** (types for the resource modules not yet migrated to generated Schema types; runtime only for the SDK transport and the SDK-based webhook verifier). Dependencies: the core, `@distilled.cloud/stripe` and `@distilled.cloud/core` (both pinned exactly in the catalog, at the same version).

## Boundary

Imports only `@thomasfosterau/effect-payments` from this workspace (`.fallowrc.json` zone `stripe`, allow `core`). Distilled is imported only by `StripePayments.ts` and `internal/distilled.ts`, and only through its subpaths (`@distilled.cloud/stripe/stripe` for the operations, `/Credentials`, `/Protocol`, `/Retry`, `@distilled.cloud/core/response-validation`); a public declaration names `@distilled.cloud/stripe/Credentials` and nothing else of Distilled's, because the operations' module is a 7.5 MB declaration every consumer would type-check (`tests/dist-consumer/src/distilledDeclarations.ts`).

## Invariants

- **`layerConfig` never fails to build.** `StripeHttp.layerConfig` (and `StripePayments.layerConfig`, through `internal/distilled.ts`) reads the key (`STRIPE_API_KEY` by default) on every call, never at layer construction: from the calling fiber's `ConfigProvider` first, then from the one the layer was built under (so a provider attached with `Layer.provide` is honoured). Absent, empty or unreadable, the call fails with the core's `PaymentsUnavailable` before anything is sent. Effect's `ConfigProvider` treats a literal empty string as a missing value, so an empty `STRIPE_API_KEY` is read as absent by the provider itself; the code's own empty check stays as the guard for a `ConfigProvider` built with `preserveEmptyStrings: true`. `layerFromEnv` likewise fails with `PaymentConfigError` for an empty variable (`tests/StripeHttp.test.ts`, `tests/StripePayments.layerConfig.test.ts`). This is gardeneria's `stripeStubLayer` / call-time `STRIPE_SECRET_KEY` posture ("not configured ≡ down"). `layer` / `layerFromEnv` keep failing the build with `PaymentConfigError`.
- **Stripe failures become neutral errors in one place**: `toPaymentsError` (`internal/error.ts`), fed by `classifyResponse` (status + the `Schema`-decoded `{ error: { type, code, message, param } }` envelope, 401 / 403 / 429 winning over the body's `type`, as in the SDK) from the fetch transport and from the Distilled client, and by the SDK transport's `handleStripeError`. Distilled's error classes carry neither the status nor the whole vendor error object, so the Distilled client watches each response through the `HttpClient` it hands Distilled and classifies that; a Distilled failure with no response behind it is a connection failure or a `PaymentProviderError` coded by its tag. A resource module or capability never throws and never leaks an SDK or Distilled error class.
- **`StripePayments` pins `Stripe-Version` on every request, following Distilled** (`DISTILLED_API_VERSION` in `internal/apiVersion.ts`, re-exported from `StripePayments.ts`, unless configured, through `withRequestOptions`): Distilled sends none of its own. Owner decision on #146: the pin is the API version the pinned Distilled release's schemas are generated from (`2026-07-29.dahlia` at `1.0.0-rc.13`: the `com.stripe.api#Stripe` service's `version` in `packages/stripe/.generated-specs/stripe.json` at the release commit; the tarball has no such constant), and it **moves with every Distilled bump**. `tests/distilledApiVersion.test.ts` keys the followed version by the installed Distilled version and fails on a release it does not list: on a bump, update the constant and that table together and re-check the fields `internal/mapping.ts` reads. The resource modules and `StripeHttp` keep `DEFAULT_API_VERSION` (basil) until slice 3. Distilled's schemas mark fields required that a response at an older configured version lacks, so the client also pins Distilled's `ResponseValidation` to lenient and the capability layers decode the fields they map (`internal/mapping.ts`). Distilled's own retries are switched off; the client applies the SDK's policy, a per-attempt timeout and redirect refusal itself (`tests/StripePayments.wire.test.ts`).
- **Top-level layer constructions in `StripePayments.ts` are `/* @__PURE__ */`, and the capability modules are namespace imports by subpath**, so a bundler drops the capabilities (and the Distilled operations, with their schemas) a program does not use. A named import from the core's barrel turns `CustomerNS.Customers` into a property access a bundler must keep.
- **Only `Stripe.ts` loads `stripe` at runtime.** Everything else imports it with `import type` only (and a migrated module not at all), so a Worker bundle never contains the SDK; `tests/sdkOptional.test.ts` walks the sources' runtime import graph and `tests/dist-consumer/src/sdkOptional.ts` (in that package's `check` task) walks the emitted `dist/` graph; either fails otherwise.
- **The capabilities need a `process` global** (on Workers, `nodejs_compat`; owner decision on #146: document it, no shim). Distilled reads `process.env.DISTILLED_DEBUG_HTTP` unguarded each time it encodes a request or decodes a response (#148), so without one a call dies with a defect. Building a layer, and a `layerConfig` call with no key, never reach Distilled; `StripeHttp`, the resource modules and `Webhook.verify` never load it.
- **The key never reaches an error or a log line.** It is a `Redacted` until the header is set; a transport failure's `cause` is the underlying error, never the `HttpClientError` or `HttpClientRequest` (whose headers carry the key). `tests/StripePayments.wire.test.ts` walks every error's own-property graph for the key, because Effect's `Headers` redaction hides it from `JSON.stringify` and `String`. Distilled's `DISTILLED_DEBUG_HTTP` logging does not log the `Authorization` header, but does log URLs and bodies (a `client_secret` included).
- **Options objects bound for the SDK go through `omitUndefined`** (`internal/omitUndefined.ts`): the SDK's parameter types declare bare `?: T`, which `exactOptionalPropertyTypes` will not let an assembled `T | undefined` satisfy. The form encoder skips `undefined` values, so the fetch transport takes assembled objects as they are.
- **Never hand-edit `schemas.ts`**; regenerate it with `generate:schemas`, because CI regenerates from the pin and diffs it (`git diff --exit-code`).
- **Migrating a resource module (#81):** add its `paths` to the pin, regenerate, replace its `Stripe.*` types with the generated ones, and list it in `tests/dist-consumer/src/declarationsFreeOfSdk.ts` (its `.d.ts` must not import `stripe`).

## Terms

- **Transport** — `StripeHttp` (`StripeHttp.ts`, a `Context.Service` with one `request({ method, path, params, idempotencyKey?, stripeAccount?, upload? })` resolving to the response JSON). The default implementation (`StripeHttp.make` / `layer` / `layerFromEnv`) runs over `effect/http`'s `HttpClient`: `Redacted` key as a bearer token, `Stripe-Version` pinned (`DEFAULT_API_VERSION`, 2025-08-27.basil — the version the `stripe` SDK's types (18.5.x), the optional peer's range and the generated schemas' pinned spec all describe; not the capability layers' `DISTILLED_API_VERSION`) unless configured, form-encoded params (`internal/form.ts`, the SDK's `qs` encoding), redirects refused, the SDK's retry policy and backoff with one generated `Idempotency-Key` across a `POST`'s attempts, Files API uploads as multipart to `files.stripe.com`.
- **SDK transport** — `Stripe.ts`: an SDK client as `StripeService` (the tag lives in `internal/sdk.ts` so the webhook verifier can require it without loading the SDK) and `StripeHttp` over `stripe.rawRequest` (`Stripe.transport`). The only module that loads `stripe` at runtime; not re-exported from the barrel.
- **Resource module** — `Customer.ts`, `Treasury.FinancialAccount.ts`, …: `create` / `retrieve` / `update` / `del` / `list` as the resource supports, each one ``stripeRequest(method, path`/v1/…/${id}`, params, options)``, with a trailing `options?: RequestOptions | undefined` (`{ idempotencyKey?, stripeAccount? }`, the SDK's per-call options) on every operation, a migrated module's `stripeRequestDecoded` included (`tests/RequestOptions.test.ts` walks the sources and fails on one that lacks it) (`internal/index.ts`; `path` URI-encodes each interpolated segment). Until migrated, results are typed with the `stripe` package's declarations and are **not decoded** (the escape hatch is full-fidelity); a **migrated** module (see _Generated schemas_) is typed by generated Schemas and decodes.
- **Generated schemas** — `src/internal/generated/schemas.ts`, written by `generate:schemas` (`scripts/generate-stripe-schemas.ts`, `@effect/openapi-generator`) from the Stripe OpenAPI spec pinned in `scripts/stripe-spec.json` (tag, commit, SHA-256 of `spec3.json`, and the API version, which equals `DEFAULT_API_VERSION` and the `stripe` peer's; `tests/generatedSchemas.test.ts` checks the first). A **migrated** module (`CheckoutSession.ts`, `BillingPortal.Session.ts`, `Customer.ts`, `Product.ts`, `Price.ts`, `Subscription.ts`, `SubscriptionSchedule.ts`, `Invoice.ts`) re-exports the generated resource schema (`Session`, `Customer`, …, plus its list page and, where Stripe answers one, its deleted form) and parameter types, and runs `stripeRequestDecoded` (`internal/decode.ts`). The generator workarounds (expandable fields, and the resources Stripe's error object `api_errors` carries, collapsed to `string | open JSON object`, lenient response enumerations, `?: T | undefined` request types, response bounds dropped, `/* @__PURE__ */` schemas) are documented in `scripts/prepareSpec.ts` and `scripts/postProcess.ts`.
- **Distilled client** — `internal/distilled.ts`: the internal `StripeClient` service the capability layers are built over, whose `call(method, operation, input, idempotencyKey?)` runs one Distilled operation under the request policy above and resolves to the response JSON, unchecked. Built from Distilled's `Credentials` in context (`layerFromContext`), or from configuration (`layer` / `layerFromEnv` / `layerConfig`, mirroring `StripeHttp`'s).
- **Capability layers** — `StripePayments.customersLayer` … `refundsLayer`, `checkoutSessionsLayer`, `billingPortalSessionsLayer`, `capabilities` (all of them over Distilled's `Credentials` and an `HttpClient`, at the default policy), `layer` / `layerFromEnv` / `layerConfig` (credentials and policy from configuration; need an `HttpClient`). They map neutral params onto the Distilled operation's input (`omitUndefined`, since Distilled's input types declare bare `?: T`; a path id is refused unless it is a non-empty string; the neutral `idempotencyKey` of a create / confirm becomes `Idempotency-Key` after `IdempotencyKey.validate`; without one, a retryable `POST` gets a generated key shared by its attempts) and **decode** each response with a `Schema` narrowed to the fields they read (`internal/mapping.ts`), so a malformed 2xx fails with `PaymentProviderError`.
- **Webhook** — `Webhook.verify` is the default verifier: WebCrypto HMAC-SHA256 (`internal/signature.ts`), constant-time compare, a tolerance window read from `Clock`, then a lenient `Schema` decode of the envelope; `decodeHandledEvent` narrows it to `handledEventTypes`. `Webhook.constructEvent` / `constructEventAsync` wrap the SDK verifier and stay as the optional alternative (they need `StripeService` from `Stripe.layer`). The signing secret is a `Redacted` and never reaches a `SignatureVerificationError`.
