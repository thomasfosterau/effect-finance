# packages/payments-stripe — `@thomasfosterau/effect-payments-stripe`

Stripe: the neutral capabilities as `Layer`s (`StripePayments`) plus one resource module per Stripe API resource as a provider escape hatch, all over a fetch-only transport. Peers: `effect`, and `stripe` **optional** (types for the resource modules; runtime only for the SDK transport and the SDK-based webhook verifier). Dependency: the core.

## Terms

- **Transport** — `StripeHttp` (`StripeHttp.ts`, a `Context.Service` with one `request({ method, path, params, idempotencyKey?, stripeAccount?, upload? })` resolving to the response JSON). The default implementation (`StripeHttp.make` / `layer` / `layerFromEnv`) runs over `effect/unstable/http`'s `HttpClient`: `Redacted` key as a bearer token, `Stripe-Version` pinned (`DEFAULT_API_VERSION`, 2025-02-24.acacia — the version the `stripe` SDK's types describe) unless configured, form-encoded params (`internal/form.ts`, the SDK's `qs` encoding), redirects refused, the SDK's retry policy and backoff with one generated `Idempotency-Key` across a `POST`'s attempts, Files API uploads as multipart to `files.stripe.com`.
- **SDK transport** — `Stripe.ts`: an SDK client as `StripeService` (the tag lives in `internal/sdk.ts` so the webhook verifier can require it without loading the SDK) and `StripeHttp` over `stripe.rawRequest` (`Stripe.transport`). The only module that loads `stripe` at runtime; not re-exported from the barrel.
- **Resource module** — `Customer.ts`, `Treasury.FinancialAccount.ts`, …: `create` / `retrieve` / `update` / `del` / `list` as the resource supports, each one ``stripeRequest(method, path`/v1/…/${id}`, params)`` (`internal/index.ts`; `path` URI-encodes each interpolated segment). Results are typed with the `stripe` package's declarations and are **not decoded** (the escape hatch is full-fidelity). (Before Effect 4 each operation went through a `Request` + `RequestResolver` pair with request caching on reads. Effect 4 removed `Effect.withRequestCaching` and the global request cache — `RequestResolver.withCache` still exists, per resolver — and a resolver built per call batched nothing, so #38 removed the pairs.)
- **Capability layers** — `StripePayments.customersLayer` … `refundsLayer`, `checkoutSessionsLayer`, `billingPortalSessionsLayer`, `capabilities` (all of them over an existing `StripeHttp`), `layer` / `layerFromEnv` / `layerConfig` (fetch transport + capabilities; need an `HttpClient`). They map neutral params onto Stripe's and **decode** each response with a `Schema` narrowed to the fields they read (`internal/mapping.ts`), so a malformed 2xx fails with `PaymentProviderError`.
- **Webhook** — `Webhook.verify` is the default verifier: WebCrypto HMAC-SHA256 (`internal/signature.ts`), constant-time compare, a tolerance window read from `Clock`, then a lenient `Schema` decode of the envelope; `decodeHandledEvent` narrows it to `handledEventTypes`. `Webhook.constructEvent` / `constructEventAsync` wrap the SDK verifier and stay as the optional alternative (they need `StripeService` from `Stripe.layer`). The signing secret is a `Redacted` and never reaches a `SignatureVerificationError`.

## Local invariants

- **`layerConfig` never fails to build.** `StripeHttp.layerConfig` (and `StripePayments.layerConfig` over it) reads the key (`STRIPE_API_KEY` by default) through the current `ConfigProvider` on every call, never at layer construction; absent, empty or unreadable, the call fails with the core's `PaymentsUnavailable` before anything is sent. This is gardeneria's `stripeStubLayer` / call-time `STRIPE_SECRET_KEY` posture ("not configured ≡ down"). `layer` / `layerFromEnv` keep failing the build with `PaymentConfigError`.

- **Stripe failures become neutral errors in one place**: `toPaymentsError` (`internal/error.ts`), fed by the fetch transport's `classifyResponse` (status + the `Schema`-decoded `{ error: { type, code, message, param } }` envelope, 401 / 403 / 429 winning over the body's `type`, as in the SDK) and by the SDK transport's `handleStripeError`. A resource module never throws and never leaks an SDK error class.
- **Only `Stripe.ts` loads `stripe` at runtime.** Everything else imports it with `import type` only, so a Worker bundle never contains the SDK; `tests/sdkOptional.test.ts` walks the sources' runtime import graph and `tests/dist-consumer/src/sdkOptional.ts` (in that package's `check` task) walks the emitted `dist/` graph; either fails otherwise.
- **The key never reaches an error or a log line.** It is a `Redacted` until the header is set; a transport failure's `cause` is the underlying error, never the `HttpClientRequest` (whose headers carry the key).
- **Options objects bound for the SDK go through `omitUndefined`** (`internal/omitUndefined.ts`): the SDK's parameter types declare bare `?: T`, which `exactOptionalPropertyTypes` will not let an assembled `T | undefined` satisfy. The form encoder skips `undefined` values, so the fetch transport takes assembled objects as they are.

## Boundary

Imports only `@thomasfosterau/effect-payments` from this workspace (`.fallowrc.json` zone `stripe`, allow `core`).
