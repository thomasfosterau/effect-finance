# packages/payments-stripe — `@thomasfosterau/effect-payments-stripe`

Stripe: the neutral capabilities as `Layer`s (`StripePayments`) plus one resource module per Stripe API resource as a provider escape hatch, all over a fetch-only transport. Peers: `effect`, and `stripe` **optional** (types for the resource modules not yet migrated to generated Schema types; runtime only for the SDK transport and the SDK-based webhook verifier). Dependency: the core.

## Terms

- **Transport** — `StripeHttp` (`StripeHttp.ts`, a `Context.Service` with one `request({ method, path, params, idempotencyKey?, stripeAccount?, upload? })` resolving to the response JSON). The default implementation (`StripeHttp.make` / `layer` / `layerFromEnv`) runs over `effect/http`'s `HttpClient`: `Redacted` key as a bearer token, `Stripe-Version` pinned (`DEFAULT_API_VERSION`, 2025-08-27.basil — the version the `stripe` SDK's types (18.5.x), the optional peer's range and the generated schemas' pinned spec all describe) unless configured, form-encoded params (`internal/form.ts`, the SDK's `qs` encoding), redirects refused, the SDK's retry policy and backoff with one generated `Idempotency-Key` across a `POST`'s attempts, Files API uploads as multipart to `files.stripe.com`.
- **SDK transport** — `Stripe.ts`: an SDK client as `StripeService` (the tag lives in `internal/sdk.ts` so the webhook verifier can require it without loading the SDK) and `StripeHttp` over `stripe.rawRequest` (`Stripe.transport`). The only module that loads `stripe` at runtime; not re-exported from the barrel.
- **Resource module** — `Customer.ts`, `Treasury.FinancialAccount.ts`, …: `create` / `retrieve` / `update` / `del` / `list` as the resource supports, each one ``stripeRequest(method, path`/v1/…/${id}`, params, options)``, with a trailing `options?: RequestOptions | undefined` (`{ idempotencyKey?, stripeAccount? }`, the SDK's per-call options) on every operation, a migrated module's `stripeRequestDecoded` included (`tests/RequestOptions.test.ts` walks the sources and fails on one that lacks it) (`internal/index.ts`; `path` URI-encodes each interpolated segment). Until migrated, results are typed with the `stripe` package's declarations and are **not decoded** (the escape hatch is full-fidelity); a **migrated** module (see _Generated schemas_) is typed by generated Schemas and decodes. (Before Effect 4 each operation went through a `Request` + `RequestResolver` pair with request caching on reads. Effect 4 removed `Effect.withRequestCaching` and the global request cache — `RequestResolver.withCache` still exists, per resolver — and a resolver built per call batched nothing, so #38 removed the pairs.)
- **Generated schemas** — `src/internal/generated/schemas.ts` (header: _generated; do not edit_), written by `scripts/generate-stripe-schemas.ts` (`vp run --filter ./packages/payments-stripe generate:schemas`) from Stripe's OpenAPI spec with `@effect/openapi-generator` (a dev dependency). The input is pinned in `scripts/stripe-spec.json`: a `stripe/openapi` tag, its commit, the SHA-256 of `spec3.json` (the script refuses anything else) and the API version (`2025-08-27.basil`, which must equal `DEFAULT_API_VERSION` and the `stripe` peer's API version; `tests/generatedSchemas.test.ts` checks the first). `scripts/prepareSpec.ts` cuts the spec to the pinned `paths` and works around what the generator mishandles: it drops `default` (error) responses, drops string `pattern`s (rc.118 cannot revive them), adds `null` to `nullable` `anyOf`s and enums (the generator drops it), keeps a `deepObject` query parameter optional, and **collapses expandable fields** (`x-expansionResources`) to `string | open JSON object` so one resource does not drag in the whole resource graph. A migrated module (`CheckoutSession.ts`, `BillingPortal.Session.ts`) re-exports the generated `Session` schema and parameter types and runs `stripeRequestDecoded` (`internal/decode.ts`): the body is decoded and a mismatch fails with `PaymentProviderError`. `scripts/postProcess.ts` then rewrites the generator output: response enumerations become the core's lenient `Enumeration.fromWire` (`Known | Other(raw)`; the `object` discriminators stay closed), request types keep only their type with `?: T | undefined` for optionals and without the generator's open `& { [x: string]: Json }` rest on every object (the repository convention; a forwarded `undefined` could not pass that rest when nested), and every top-level schema is `/* @__PURE__ */` so a bundler drops the ones an entry point does not reach. `prepareSpec` applies the nullable rewrites and drops response `maxLength` / `minimum` / `maximum` / integer-ness on response schema nodes only (components and inline operation responses; never a `properties` map, where `maximum` can be a field name) (a response that has already taken effect must never fail over a documented bound), and fails on any `pattern` that is not a `^/v1/` list-URL template. CI regenerates from the pinned spec and diffs it (`git diff --exit-code`). To migrate another module: add its `paths` to the pin, regenerate, and replace its `Stripe.*` types with the generated ones; its `.d.ts` must not import `stripe` (`tests/dist-consumer/src/declarationsFreeOfSdk.ts` lists the migrated entries).
- **Capability layers** — `StripePayments.customersLayer` … `refundsLayer`, `checkoutSessionsLayer`, `billingPortalSessionsLayer`, `capabilities` (all of them over an existing `StripeHttp`), `layer` / `layerFromEnv` / `layerConfig` (fetch transport + capabilities; need an `HttpClient`). They map neutral params onto Stripe's (the neutral `idempotencyKey` of a create / confirm becomes the request's `idempotencyKey`, i.e. `Idempotency-Key`, after `IdempotencyKey.validate`; no key sends none) and **decode** each response with a `Schema` narrowed to the fields they read (`internal/mapping.ts`), so a malformed 2xx fails with `PaymentProviderError`.
- **Webhook** — `Webhook.verify` is the default verifier: WebCrypto HMAC-SHA256 (`internal/signature.ts`), constant-time compare, a tolerance window read from `Clock`, then a lenient `Schema` decode of the envelope; `decodeHandledEvent` narrows it to `handledEventTypes`. `Webhook.constructEvent` / `constructEventAsync` wrap the SDK verifier and stay as the optional alternative (they need `StripeService` from `Stripe.layer`). The signing secret is a `Redacted` and never reaches a `SignatureVerificationError`.

## Local invariants

- **`layerConfig` never fails to build.** `StripeHttp.layerConfig` (and `StripePayments.layerConfig` over it) reads the key (`STRIPE_API_KEY` by default) on every call, never at layer construction: from the calling fiber's `ConfigProvider` first, then from the one the layer was built under (so a provider attached with `Layer.provide` is honoured). Absent, empty or unreadable, the call fails with the core's `PaymentsUnavailable` before anything is sent. Effect rc.118's `ConfigProvider` treats a literal empty string as a missing value (it was a present `""` through rc.117), so an empty `STRIPE_API_KEY` is read as absent by the provider itself; the code's own empty check stays as the guard for a `ConfigProvider` built with `preserveEmptyStrings: true`. `layerFromEnv` likewise fails with `PaymentConfigError` for an empty variable (`tests/StripeHttp.test.ts`, `tests/StripePayments.layerConfig.test.ts`). This is gardeneria's `stripeStubLayer` / call-time `STRIPE_SECRET_KEY` posture ("not configured ≡ down"). `layer` / `layerFromEnv` keep failing the build with `PaymentConfigError`.
- **Stripe failures become neutral errors in one place**: `toPaymentsError` (`internal/error.ts`), fed by the fetch transport's `classifyResponse` (status + the `Schema`-decoded `{ error: { type, code, message, param } }` envelope, 401 / 403 / 429 winning over the body's `type`, as in the SDK) and by the SDK transport's `handleStripeError`. A resource module never throws and never leaks an SDK error class.
- **Only `Stripe.ts` loads `stripe` at runtime.** Everything else imports it with `import type` only (and a migrated module not at all), so a Worker bundle never contains the SDK; `tests/sdkOptional.test.ts` walks the sources' runtime import graph and `tests/dist-consumer/src/sdkOptional.ts` (in that package's `check` task) walks the emitted `dist/` graph; either fails otherwise.
- **The key never reaches an error or a log line.** It is a `Redacted` until the header is set; a transport failure's `cause` is the underlying error, never the `HttpClientRequest` (whose headers carry the key).
- **Options objects bound for the SDK go through `omitUndefined`** (`internal/omitUndefined.ts`): the SDK's parameter types declare bare `?: T`, which `exactOptionalPropertyTypes` will not let an assembled `T | undefined` satisfy. The form encoder skips `undefined` values, so the fetch transport takes assembled objects as they are.

## Boundary

Imports only `@thomasfosterau/effect-payments` from this workspace (`.fallowrc.json` zone `stripe`, allow `core`).
