  - **Matching:** an exhaustive match over a status, price type or interval (`Match.exhaustive`, a `switch` with a `never` default, a `Record<PaymentStatus, …>`) needs a case for `Other` with `Enumeration.isOther(status)` (a bare `status._tag` check does not type-check, since the known members are plain strings).   - **Stripe:** payment intent `status`, subscription `status`, refund `status`, price `type` and recurring `interval` decode leniently, so one unrecognised value never fails the call or its list page.
  - **PayPal / Airwallex:** an unrecognised order, subscription or refund status (and PayPal billing interval unit) becomes `Other` rather than a neutral fallback.

- [#87](https://github.com/thomasfosterau/effect-finance/pull/87) [`9bbb1ad`](https://github.com/thomasfosterau/effect-finance/commit/9bbb1ad8b8e3f1b07823132edc48b628dddf4f63) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - A neutral, branded `idempotencyKey` on the create and confirm operations, so a caller's retry of a timed-out write is one logical write on every provider (closes [#55](https://github.com/thomasfosterau/effect-finance/issues/55) and [#66](https://github.com/thomasfosterau/effect-finance/issues/66)).

  - **Core.** New `IdempotencyKey` module (`@thomasfosterau/effect-payments/IdempotencyKey`, also exported from the barrel): a branded `Schema` for a key of 1 to 64 characters from `A-Z a-z 0-9 _ -`, `IdempotencyKey.generate` (a random UUID, as an `Effect`) and `IdempotencyKey.validate`. The optional `idempotencyKey?: IdempotencyKey` is added to `Customer.CreateParams`, `Product.CreateParams`, `Price.CreateParams`, `PaymentIntent.CreateParams` / `ConfirmParams`, `Subscription.CreateParams`, `Refund.CreateParams` and `CheckoutSession.CreateParams` (every create / confirm that each provider implementing it can honour). It is not on updates, `Subscription.cancel`, `PaymentIntent.cancel` or `BillingPortal.create`. The key is optional.
  - **Stripe, PayPal, Airwallex.** Each maps the key onto its vendor mechanism: `Idempotency-Key`, `PayPal-Request-Id`, and the body's `request_id` (in place of the fresh per-call id). A key that is not a valid `IdempotencyKey` (a raw string from untyped code) fails with `PaymentInvalidRequestError` before anything is sent.
  - **The pattern.** Create one key per logical write before the first attempt and reuse it on every retry; retry only when the outcome is unknown or the write was not applied (`PaymentNetworkError`, `PaymentProviderError` with `statusCode >= 500`, `PaymentRateLimitError`). A key reused with different parameters is a `PaymentProviderError` on Stripe (`StripeIdempotencyError`); PayPal's and Airwallex's behaviour is unverified. See "Retrying a write safely" in the core README.
  - Stripe's and Airwallex's key-length limits and replay windows could not be checked against their documentation and are documented as unverified (PayPal's: see its own entry).

- [#64](https://github.com/thomasfosterau/effect-finance/pull/64) [`02df7cd`](https://github.com/thomasfosterau/effect-finance/commit/02df7cd316eeba8355de32a885ff3cfd5ab8eac4) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Redacted secrets and decoded responses in the PayPal and Airwallex providers.

  - `PayPalConfig.clientSecret` and `AirwallexConfig.apiKey` are `Redacted<string>`: wrap the value with `Redacted.make(...)` when you call `layer`. `layerFromEnv` reads it with `Config.Redacted`, and a missing or empty variable fails with `PaymentConfigError`. The client id is a plain string.
  - Every vendor response a capability reads is decoded with a `Schema` narrowed to the fields it maps. A 2xx body that does not match (a missing id, a non-numeric amount, a list without its collection) fails with `PaymentProviderError` (`"PayPal returned a malformed … response"`) instead of producing an entity built from `undefined`. Unknown fields are ignored and statuses keep their lenient mapping. A PayPal list page with no collection reads as empty. Airwallex metadata keeps only its string values. A PayPal plan's `interval_count` must be a positive integer, a subscription `quantity` a whole number, and a PayPal partial refund whose capture has no amount fails rather than assuming USD.
  - `AirwallexClient.request` returns `unknown`; a custom client that implements the service returns the body as-is.
  - A transport failure's `PaymentNetworkError` carries only the underlying failure, never the `HttpClientError`, whose request holds the credential headers.

- [#151](https://github.com/thomasfosterau/effect-finance/pull/151) [`56db620`](https://github.com/thomasfosterau/effect-finance/commit/56db620a03c5cd5efc60e09ef898010d0094cb19) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - `PayPalPayments` runs on Distilled's PayPal operations (`@distilled.cloud/paypal`), and the package publishes no PayPal REST client of its own ([#146](https://github.com/thomasfosterau/effect-finance/issues/146)).

  - **Dependencies.** `@distilled.cloud/paypal` and `@distilled.cloud/core`, both pinned exactly to `1.0.0-rc.15`, the same version as the Stripe package's (about 9 MB installed, with core's `graphql` dependency). A bundler keeps only the capabilities you use: a bundle of `productsLayer` alone is about 40 KB minified (14 KB gzipped), and one of every capability about 117 KB (27 KB gzipped), with `effect` external.
  - **The `effect` peer is `^4.0.0`.** Distilled declares the peer `effect: ^4.0.0`, which no `4.0.0-rc.*` prerelease satisfies, so this package requires the same, as the Stripe package does. The core and the Airwallex provider accept `>=4.0.0-rc.118`.
  - **The capabilities need a `process` global.** Distilled reads `process.env.DISTILLED_DEBUG_HTTP`, unguarded, on every request and response, so without a `process` global every capability call dies with a defect. On Cloudflare Workers, enable the `nodejs_compat` compatibility flag. Building the layers and the OAuth login do not need it. While `DISTILLED_DEBUG_HTTP` is set, Distilled logs each request's method and path template and each response's status to `console.error`, and nothing else.
  - **Layers.** `PayPalPayments.layer(config)` / `layerFromEnv()` log in with OAuth client credentials (one shared, time-boxed login; the token refreshed a minute before it expires and forgotten after a 401) at the endpoint `PAYPAL_ENV` / `environment` select, or `PAYPAL_BASE_URL` / `baseUrl`, and need an `HttpClient`. `PayPalConfig` and `PayPalEnvironment` are exported from `./PayPalPayments`, and as types from the package root. The individual capability layers (`productsLayer` … `refundsLayer`) and `capabilities` require Distilled's `Credentials` (from `@distilled.cloud/paypal/Credentials`: an access token, as a `Redacted<string>`, and base URL, e.g. `fromApiKey({ apiKey: Redacted.make(token), apiBaseUrl })`) and an `HttpClient`, and send that token as it is, with no login or refresh; providing `Credentials` yourself means depending on `@distilled.cloud/paypal` at exactly this package's version of it.
  - **Request policy.** `Content-Type` and `Accept: application/json` on every request (PayPal answers a bodyless `POST` without one with 415). The neutral `idempotencyKey` is sent as `PayPal-Request-Id` on six writes (order create and capture, product, plan and subscription create, capture refund) and nowhere else. Nothing is retried, each request times out after `timeout` (80 s by default), and every failure maps onto the neutral `PaymentsError` channel from the response's status and PayPal's error body; no Distilled error class reaches a caller. Distilled's response validation is lenient, even under its `ResponseValidation.strict`, so a response is never refused over a field the capabilities do not read; the fields they map are decoded.
  - **Id and item checks.** A path id that is not a non-empty string fails with `PaymentInvalidRequestError` (`The product id must be a non-empty string`, `param: "id"`) before anything is sent, and so does `Subscription.create` without an item (`param: "items"`).
  - **Calls the capabilities do not cover.** Use `@distilled.cloud/paypal`'s operations directly, with an access token of your own in its `Credentials`, at exactly this package's version of it. Its failures are Distilled's error classes rather than `PaymentsError`, it retries 5xx and 429 responses by default, and its input types declare optional members as bare `?: T`, so under `exactOptionalPropertyTypes` omit an absent member rather than pass `undefined`.

- [#63](https://github.com/thomasfosterau/effect-finance/pull/63) [`0b1c2f2`](https://github.com/thomasfosterau/effect-finance/commit/0b1c2f27a2dec5690cde06a4227bc80ec73f9329) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Time-box every request the PayPal and Airwallex providers make.

  - **The token login has a timeout** (`loginTimeout` on `PayPalConfig` / `AirwallexConfig`, in milliseconds, default 30 000), so a login the vendor accepted but never answers cannot stall the requests waiting for a token. A login that runs out of time is aborted and fails with `PaymentNetworkError`, and the next caller logs in afresh.
  - **Resource requests have a timeout** (`timeout`, in milliseconds, default 80 000 — the Stripe client's per-attempt default). A request that runs out of time, response body included, is aborted and fails with `PaymentNetworkError`.
  - Both timeouts are checked when the configuration is read (PayPal's `layer`, Airwallex's `make` / `layer`). `Infinity` turns a timeout off. `0`, a negative number or `NaN` fails with `PaymentConfigError`.
  - Two limits to know about. `timeout` does not cover getting a token. And a write (a non-GET) that times out has an unknown outcome, so don't blindly retry it without the same `idempotencyKey`.

It is not public API and application code should not import it. It holds:

  - `shareLogin`, one in-flight token login shared by every waiting caller;
  - the vendor-neutral integer money core (`exponentFrom`, `scaleToMinor`, `parseDecimal`, `decimalText`, `formatDecimal`, `checkMinorUnits`);
  - the token-login plumbing of an OAuth-style provider (`tokenCache`, `send`, `networkError`, `timedOut`, `timeoutOf`, `isAbsoluteHttpUrl`, `isOk`);
  - the request helpers of a provider built over a generated operation client (`omitUndefined`, `checkId`, `stringField`, `observeResponses`, `rejectedError`).

  None of them names a vendor or a client library. The Stripe, PayPal and Airwallex providers import these helpers from it rather than carrying copies of their own.
